| --- | --- | --- | --- |
| v0.1 | Harness 能否成为公平且可持续行动的扑克 Agent？ | 双人规则状态机、独立 Iris、四个受限工具、公开统计持久化 | 合法行动、私有信息投影、提交关联、取消与兜底的闭环 |
| v0.2 | 统计记忆能否按局面使用并接受评估？ | 条件画像与样本区间、确定性金额事实、历史回放、配对发牌对照 | 4,500 手牌规则基线；条件画像未证明收益提升 |
| v0.3 | 操作是否顺畅，预算和记忆依据是否可核对？ | 快捷下注、可保存的每轮预算、当前摘要注入、提供 / 读取 / 引用 trace | 35 项测试、浏览器交互回归和预构建包检查 |

## v0.1：先完成受限 Agent 与业务闭环

**问题。** 编程 Harness 的默认能力太宽，模型也不能拥有整张牌桌的隐藏状态。还需要判断某个异步结果究竟属于哪次行动。

**方案。** 规则引擎持有完整牌局，按座位生成视图；Iris 新建会话，移除全局工具与工作区上下文，只提供观察、记忆、胜率抽样和提交行动。使用 `handId + revision` 绑定唯一提交，时限内未得到合法结果就取消并明确兜底。记忆先保存人类公开动作的累计计数和证据编号。

**效果与取舍。** 先验证轮次、筹码和能力边界，再考虑复杂记忆；对手身份与统计可以跨重启复用，但不能把模型人格设定当作职业水平，也没有六人桌或策略自迭代。此阶段仅提供当前结束手牌的复盘展示。

## v0.2：把记忆、解释和评估分开

**问题。** 总体弃牌率无法区分位置与下注轮；没有实际回应分母就容易误读风格。模型解释和少量牌局输赢不能证明记忆有效。

**方案。** schema v2 增加下注轮、位置、尺度下的回应次数、弃牌区间和证据；规则引擎输出可争夺底池赔率、退款等确定性事实。保存决策 trace 和更新前画像，增加历史选择、公开事件回放和证据跳转。评估使用固定种子、配对牌组、交换庄位、隔离记忆组，对照无记忆、累计统计和条件画像。

**效果与取舍。** 4,500 手牌规则对照具有可重复性，条件画像没有显示收益提升；保留这一结果作为后续研究基线。统计仍来自公开行为，未升级为向量经验库；历史有 100 条 / 2 MiB 读取窗口，尚无多文件事务或中断恢复。

## v0.3：改进操作、预算与记忆归因

**问题。** 滑块难选常用金额，BB 与筹码混用易误解；固定 25 秒 / 6 次预算不适合所有模型。复盘“没有引用”容易被读成“完全没有长期记忆影响”，范围推测也可能被误当画像。

**方案。** BB / 底池比例快捷金额同栏展示，确认后才提交；输入支持 0.5 BB 步进与单筹码手动精度，滑块作为辅助。预算默认 60 秒 / 10 次，可在手牌间保存；每轮复制到提示、取消信号、工具计数和历史 trace。每次输入主动提供当前公开统计摘要，按需读取条件详情，分别记录提供、读取与显式引用，拒绝虚构、空样本与过期引用。界面随可用高度伸展，未亮牌明确说明原因。

**效果与取舍。** 35 项测试与浏览器交互验证通过；复用同一个 Agent 时，新预算和新摘要可正确生效。增加预算不等于河牌超时已经消除，引用记录也不能证明记忆导致收益改善；真实模型成本与长期稳定性仍需单独评估。

## 文档维护约定

- 改实现时更新 `technical-design.md` 的当前事实，不再为每个小版本复制一份完整方案。
- 一个版本完成时，在此文追加“问题 → 方案 → 效果与取舍”，记录关键选择及证据。
- 面向用户的新增、改进、修复和升级注意事项写入根目录 `CHANGELOG.md`，最新版本在前。
- 发布指南记录 npm 与安装验收、市场 PR 的实际进度；只有各阶段完成后才更新对应状态。
- `archive/` 保留现有里程碑快照，旧路径作为兼容入口；日常阅读从当前设计开始。
