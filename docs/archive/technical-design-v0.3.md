# RiverMind v0.3 技术方案

> 历史快照，保留该里程碑的实现与验证记录；当前规范统一见 [当前技术设计](../technical-design.md)。源码链接指向当前源码，需结合对应 Git 提交理解。

当前版本 `0.3.0`，在 v0.2 的双人德扑、受限 Agent、条件统计记忆和历史复盘基础上，优化下注交互、Iris 决策预算和记忆引用的可观测性。完整的规则、工具隔离及记忆流程见 [v0.2 基础方案](technical-design-v0.2.md)。

## 1. 本版解决的问题

| 问题 | 方案 | 当前效果 |
| --- | --- | --- |
| 长滑块难以定位常用下注；输入过程被立即截断，难以输入小数 BB | 快捷金额、BB / 筹码输入、合法性提示，滑块保留为辅助 | 点选常用金额，确认后才下注；支持精确到 1 筹码的小数 BB |
| 固定 25 秒 / 6 次工具不适合所有模型和复杂行动 | 默认 60 秒 / 10 次；手牌间自定义并持久保存 | 下一次决策使用保存的预算，重启后恢复 |
| 超时提示缺少当次上限，难以分辨工具耗尽与模型延迟 | 动态等待计时、分类兜底提示、trace 保存预算 | 复盘能核对当时配置、工具尝试及失败类型 |

本版保留扑克规则、统计记忆更新和规则评估算法，调整 DSH 记忆摘要注入与引用展示。

## 2. 下注交互

### 2.1 先选金额，再确认

`BetControls` 翻牌前直接显示 2、2.5、3、5、10 BB 与全下；翻牌后同一栏优先展示 1/3、1/2、3/4 底池、满池与全下，随后展示固定 BB 金额。所有快捷金额默认展示，无须展开折叠区。宽桌面尽量排成一行；空间不足时该栏横向滚动，金额输入框保持可见。手机把输入框放到下一行。快捷按钮只修改选中金额，不会提交行动。点击“下注至 / 加注至”才向后端提交。固定按钮不在合法范围时禁用，不会偷偷截到另一金额；短额全下时仅合法全下选项可用。

行动按钮同时显示 BB 与筹码数，例如“加注至 2.5 BB / 50 筹码”；跟注按钮显示此次追加金额，加注按钮显示本轮累计金额。等待对手或手牌结束时隐藏金额编辑，按钮不再显示无意义的“下注至 0 BB”。

输入框可切换 BB / 筹码，切换有效金额时保留同一筹码值。BB 单位的上下箭头按 0.5 BB 步进，筹码单位按 1 筹码步进。交互步幅不改变提交精度，手动输入仍支持 2.35 BB（47 筹码）等合法金额。输入中允许暂时清空或保留尚未合法的值；界面提示错误并禁用提交，继续输入时不自动改写数值。新行动版本到来时默认选中最小合法加注。

最小单位仍为 1 筹码。盲注 10 / 20 时：

| 输入 | 最终提交 |
| --- | --- |
| 2.5 BB | `amount: 50` |
| 2.35 BB | `amount: 47` |
| 47 筹码 | `amount: 47` |
| 2.333 BB | 非整数筹码，提示错误 |

**金额是本轮累计投入，并非本次追加。** 例如已经投入小盲 10，选 2.5 BB 表示下注至 50，实际追加 40。后端继续使用 `Number.isSafeInteger`、轮次和合法范围校验，不信任客户端换算。

### 2.2 底池比例

翻牌后提供 1/3、1/2、3/4 底池和满池。面对下注时，这些按钮表示“跟注后再加注相应底池比例”：

```text
target = ownStreetBet + toCall + round(contestablePotAfterCall × fraction)
```

使用已有确定性 `facts.contestablePotAfterCall`，排除无法争夺的未跟注金额。按整数筹码四舍五入，再检查合法加注范围。

例：当前底池 80，你本轮已投入 0，需跟注 40；跟注后底池 120。选择半池表示再加注 60，最终下注至 100。底池快捷按钮的辅助提示明确“跟注后再加注”的语义。

折叠区改为“滑动选额”，仅放置 1 筹码步长的滑块；快捷金额全部移到同一栏。

### 2.3 随窗口伸展的牌桌

桌面布局按可用高度分配空间：DSH 插件使用宿主面板高度，本地预览使用浏览器视口高度。标题和操作区保持自然高度，牌桌与右侧记录区共同占用剩余空间，全屏不会继续使用固定的 340px 牌桌。右侧长记录在面板内滚动，不撑高整张牌桌。

公共牌、底池和本轮下注额放在同一个居中区域；座位和桌面边距随牌桌高度变化。牌桌自身的容器查询在高度达到 440px 时恢复较大的公共牌和座位，避免仅按浏览器尺寸判断嵌入面板大小。

短窗口保留紧凑操作区与牌桌最低高度；展开滑动选额、决策预算或显示异常提示后，空间不足时整页可滚动，不裁掉操作按钮。窄面板改为上下排列，手机保持正常滚动布局，不强制把内容压进一屏。

## 3. Iris 决策预算

### 3.1 设置与持久化

| 字段 | 默认 | 允许范围 |
| --- | ---: | --- |
| `timeoutSeconds` | 60 | 5～300 秒，整数 |
| `maxToolCalls` | 10 | 1～32 次，整数，包含 `submit_action` |

预算面板默认收起，摘要保留当前秒数与工具上限，展开后才显示表单。

界面预设为快速 25 / 6、标准 60 / 10、深入 120 / 16，也可直接输入。修改后须点击“保存 Iris 预算”。只有手牌之间且 Iris 空闲时可保存，后端同时检查牌局版本；活跃牌局或正在决策时返回错误，不改变当前配置。规则模式也可预先保存设置，但不使用模型预算。

配置文件 `agent-settings.json` 位于同一个运行数据目录：开发为 `.data/`，正常安装为 `$DSH_HOME/data/rivermind/`（默认 `~/.dsh/data/rivermind/`）。与四个记忆 / 牌局文件独立，重新开始训练保留预算。迁移训练记忆时可按需单独迁移此设置文件。

```json
{
  "version": 1,
  "budget": { "timeoutSeconds": 60, "maxToolCalls": 10 }
}
```

`AgentSettings` 先写权限为 `0600` 的临时文件，再原子重命名；写入成功后才替换内存设置。无效设置不会覆盖文件。旧设置损坏或版本无法识别时，保留原文件、使用启动默认值并显示提示，用户保存后修复。

支持插件启动默认值，已保存的界面设置优先：

```yaml
- insert:
    - id: rivermind
      name: '@rivermind/dsh-plugin'
      config:
        agentBudget:
          timeoutSeconds: 90
          maxToolCalls: 12
```

优先顺序为：已保存设置 > 启动 `config.agentBudget` > 内置 60 秒 / 10 次。修改 UI 设置无需重建 Agent；每次输入重新携带本次预算。

### 3.2 同一份预算如何落到执行

1. `PokerService` 为本次行动复制预算，构造 `AbortSignal.timeout(timeoutSeconds × 1000)`；覆盖会话创建、等待空闲和模型决策。
2. `DshOpponent` 收到同一份预算，放入 pending、模型输入及 `DecisionTrace`。系统提示不再固定写“六次”，要求根据当前输入执行并预留最终提交。
3. 每次工具尝试累加计数，超过当次 `maxToolCalls` 时取消输入，不执行该次工具主体。成功 / 失败工具尝试都计数，最终提交也占一次。
4. 成功提交结束本次输入；失败继续按“可免费过牌就过牌，否则弃牌”兜底。提示区分超时、工具耗尽和其他运行异常。

模型单次输出 `maxTokens: 2048` 保持不变；它不是整次行动的总 token 预算。扩大等待或工具次数可能增加模型用量，不能保证上游服务不超时，也不能证明策略更强。

### 3.3 状态与复盘

`runtime.budget` 是已保存的配置；`runtime.thinking` 仅在真实 DSH 行动期间包含开始时间和当次预算。客户端每秒刷新等待计时，实际取消由后端执行；客户端时间只用于展示。

复盘中的 `trace.budget` 是当次的预算快照，后续改设置不会改写历史。旧记录没有此字段时仍可回放。工具尝试数可能出现“11 / 10”，表示第 11 次被记录并拒绝，不表示执行了 11 个工具。

对局中仍不展示决策理由或 trace；本版没有扩大底牌和复盘的可见权限。

## 4. 记忆摘要与复盘归因

### 4.1 原有提示为什么容易误读

旧版 DSH 仅提供可选的 `recall_opponent` 工具，没有主动注入当次长期统计。模型可能只调用 `submit_action`，也可能沿用同一个 Iris 会话里此前的公开行为或旧工具结果。`memoryIds: []` 只能说明本次未显式引用，不能证明上下文中完全没有历史信息。

例如“双 A 牌面上，对手下注范围可能含 A 或成对牌”是根据当前牌面与行动推测范围。现有长期记忆只保存公开行为计数和条件统计，不保存对手隐藏底牌，不直接存储“黏性强”“诈唬有限”等自然语言画像。没有样本和引用支持时，这类性格表述不能视作已验证记忆。决策说明是模型生成的解释，也不能证明因果上的真实决策过程。

### 4.2 每次提供最新摘要，详情仍按需读取

每次 `followup` 除观察与预算外，附带当前记忆的 `id`、`handsObserved`、弃牌 / 主动入池 / 进攻手数及已有 `summary`。不包含私牌、无限增长的会话日志或全部历史证据。提示要求本轮版本替代同一会话中旧版本；需要位置、下注轮和尺度的条件证据时调用 `recall_opponent`。

模型若依据历史统计调整行动或描述风格，要求显式提交当前 `memoryIds` 并说明样本量。引用可以来自本次摘要或详情工具，但后端只接受当前版本且 `handsObserved > 0`；虚构、过期及空样本引用被拒绝。不会为了提高引用率自动添加 ID，也不强迫每次决策使用历史。

系统提示还要求把基于牌面和当前下注的范围判断标为假设，没有历史支持时不把对手黏性 / 诈唬率写成确定结论。这是提示约束，不能保证模型解释始终准确。

### 4.3 区分提供、读取、引用

`DecisionTrace.memory` 保存 `{id, handsObserved, provided, retrieved, cited}`：`provided` 表示摘要已随本次输入交给运行时；`retrieved` 表示当次成功读取详情；`cited` 表示合法提交中显式引用当前记忆版本。它们分别记录行为，不等同于模型实际采用或策略变强。

复盘以保存的行动 trace 和 `memoryIds` 展示“已提供记忆摘要，未显式引用”“已读取记忆详情，未显式引用”或“已显式引用长期记忆”，同时保留当时样本量。旧记录没有新字段时，只能从成功 `recall_opponent` 记录识别详情读取，并显示“未显式引用长期记忆”；不补造当时的提供状态，不改写旧理由或训练记忆。


### 4.3 复盘底牌可见性

复盘遵循公开牌局信息：双方摊牌时保存公开底牌，逐步回放只有到摊牌结算才显示 Iris 的牌；较早步骤显示“未亮牌”。任一方弃牌结束时，没有摊牌，Iris 的底牌在保存视图中仍是 `[null, null]`，旧记录也不会补出未公开的牌。界面明确提示“本手因弃牌结束，Iris 未亮牌；历史记录不包含其底牌”，避免把遮罩误认为复盘加载失败。回放到发牌前则显示“尚未发牌”。

```json

}
```

## 6. 验证与边界

共 35 项测试：保留扑克规则、隐藏信息、记忆与历史回放验证，新增小数 BB 与单筹码精度、非法快捷按钮、短额全下、跟注后底池比例、设置重启恢复及无效文件保护；验证活跃牌局 / AI 忙时拒绝保存、运行时采用设置的超时毫秒数，以及同一个 Agent 后续输入采用新的工具上限。记忆回归验证同一 Agent 连续输入获取最新摘要、空样本 / 虚构 / 过期引用拒绝，以及“读取”和“引用”独立记录。DSH RPC 检查包含新增设置接口、有效写入与非法 / 活跃牌局拒绝。河牌超时集成检查验证合法兜底、分类提示、复盘预算持久保存及后续配置修改不影响旧记录。

验证命令：

```sh
npm run typecheck
npm test
npm run build
```

桌面（1024×768、1366×768、1280×800、1440×800）及手机（390px）浏览器检查通过：实际规则预览中保存 / 重载预算、2.35 BB 以 47 筹码提交、非法与空值保护；合成牌局检查底池快捷按钮、忙时限制、等待计时和历史预算展示。常规桌面默认布局完整落在首屏；模拟 DSH 内嵌面板宽度 500～1100px 没有横向溢出，1000px 以上宽度默认内容可落在 800px 高的面板内，更窄时切为单列并允许纵向滚动。预算默认收起、更多金额、双单位按钮，以及旧记录 / 摘要提供 / 详情读取 / 显式引用 / 无样本的复盘状态均已检查。没有页面运行错误。插件打包检查确认许可证与文档被包含，训练数据被排除。测试使用隔离目录与模拟运行时，不写真实训练记忆，不调用付费模型。v0.2 的 4,500 手牌规则收益报告保留为历史基线，没有将其解释为 v0.3 真实模型效果。

全屏布局回归使用重建后的页面和合成牌局验证：模拟带 280px 侧栏的 1680×1047、1920×1080、1440×900、1366×768 宿主窗口，以及独立的 1000×800 / 1000×650 / 650×800 面板。准备发牌和玩家行动状态均无横向溢出，宽屏牌桌与记录区伸展到底部，公共牌与座位不重叠；120 条记录在侧栏内滚动，展开预算与更多金额仍可访问底部，调整窗口不会丢失下注草稿。另检查本地预览与 390px 手机布局。此项是浏览器中模拟宿主尺寸的布局验证，不等同于实际 DSH 模型对局。

快捷栏与底牌文案回归已通过浏览器检查：BB 箭头 2 → 2.5 → 2、筹码箭头 40 → 41 → 40，手动 2.35 BB 仍以 47 筹码提交；空值和非整数筹码继续禁用提交。翻牌前 6 个、翻牌后 10 个快捷金额直接展示，滑块折叠区没有重复按钮。1400px 面板一行完整显示，较窄面板横向滚动且没有页面横向溢出。弃牌历史显示未亮牌说明，摊牌历史只有回放到结算才显示 Iris 底牌，发牌前显示尚未发牌。使用真实规则引擎生成合成牌局与模拟接口，不读写实际训练数据。

本版仍需要在实际 DSH 模型对局中观察调整后的河牌耗时和失败率；本次工程验证不能宣称河牌超时已经消除。运行中不能修改正在进行的预算，也没有新增中止 / 重启会话按钮。

## 7. 使用方式

源码目录执行 `npm run build` 后，重启使用该源码的 DSH 实例，或使用开发入口 `npm run start:dsh`。本地无模型预览可运行 `npm run dev`。

正常安装的旧版插件不会自动切换到本地开发分支；已有 GitHub 安装需要更新安装来源后重启。本版当前在本地 `feat/v0.3` 开发，发布前先完成上述验证。
